# OSS活用と独自最適化計画

## 目的

既存の実績ある構造を参考にし、実装量とAPI費用を抑えながら、日本向けの企画・動画制作と安全なエージェント分担へ拡張する。既存OSSのコードを無断コピーせず、ライセンスを確認したうえで設計パターンだけを取り入れる。

## 参考にする構造と、このプロジェクトでの変更

| 参考プロジェクト／技術 | 取り入れる構造 | 独自の変更 |
| --- | --- | --- |
| MoneyPrinterTurbo | テーマ→脚本→素材→字幕・音声→短動画という段階分離 | 素材の権利マニフェスト、出典ハッシュ、日本語フック、再利用判定を必須化。自動投稿は持たせない |
| Hugging Face smolagents | 構造化されたツール呼び出しと、段階的なエージェントループ | ToolCalling相当を調査・QAに使い、コード実行型エージェントはサンドボックス内の下書きだけに限定 |
| Pydantic / JSON Schema | モジュール間の型と受け入れ条件を共有 | schemas/ のバージョン付き契約を正本にし、Actionsで危険フラグと承認状態を検証 |
| FFmpeg / MoviePy | 決定的な動画変換とレイヤー合成 | 本番Workerには入れず、Colab等の一時実行環境でFFmpegを主経路、MoviePyを補助経路にする |

## エージェントの分担

- Qwen planner: 需要仮説、MVP、作業分解、下位タスク案。
- DeepSeek critic: 反対意見、失敗条件、根拠不足、受け入れテスト。
- Specialist: research、product、content、video、code、qa、metricsのいずれか一件。
- 司令部（ChatGPT/Codex）: 採用、修正、PR、デプロイ、公開、課金の最終判断。

下位AIは成果物と次の作業案を返すだけで、リポジトリ書込み、秘密値変更、デプロイ、外部公開、決済、課金検索、YouTube投稿を実行できない。各成果物はJSON契約とハッシュを持ち、司令部が検査してから次のタスクを承認する。

## 日本向けShortsの初期テンプレート

目安であり、テーマと視聴データで更新する。

1. 0–2秒: 結論を先に出すフック（疑問、比較、意外な結果）。
2. 2–6秒: 視聴者の困りごとを一文で明示。
3. 6–18秒: 実演・証拠・手順を一つずつ提示。
4. 18–26秒: 例外、失敗例、または意外な反転。
5. 26–30秒: 次に試す行動とシリーズ導線。

字幕は1–2行、1行あたり14–18文字を初期値とし、画面端から安全余白を取る。フォントは環境にある日本語フォントを検出して選び、見つからない場合はレンダリングを停止して文字化けを防ぐ。字幕・SE・強調表示は内容の理解を助ける目的に限定する。

## 独自性と権利の扱い

「BANを回避する」ことを保証する機能は作らない。代わりに、次を満たさない素材は公開候補から外す。

- 自作、許諾済み、パブリックドメイン等の権利状態を記録できる。
- 元ファイルのSHA-256、取得日時、出典URL、帰属表示を記録できる。
- 独自ナレーション、解説、比較、実演など、視聴者に新しい価値を加える編集計画がある。
- 過去成果物との類似度は「危険フラグ」として検出し、閾値超過は司令部の再確認へ送る。
- 第三者動画のダウンロードや再投稿を自動化しない。

類似度スコアは判定の補助であり、プラットフォームの審査結果を保証しない。権利と利用規約が確認できない場合は生成・公開を止める。

## 低コスト運用

1. Planner/Critic/SpecialistはOpenRouterの無料モデルを先に使う。
2. 無料枠で不足する場合だけ、利用者が費用と上限を確認して低価格モデルを手動承認する。
3. 月数百円を軍資金にする場合も、初期上限を例として300円に固定し、見積額が上限を超えたら送信を止める。決済情報の登録や自動チャージは行わない。
4. 有料検索は検索件数、料金、目的を表示してから別承認する。無料検索で代替できる場合は有料経路を選ばない。
5. Colab/T4は、利用者が開始したときだけ文字起こしとレンダリングに使う。アイドル時にGPUを確保しない。

## 需要検証と有料化

サーバーに個人情報を集める前に、端末内の匿名カウンタで以下を確認する。

- 初回生成→レビュー→承認までの完了率。
- 7日以上後の更新再利用率。
- 引用付き計画の再利用率。
- 1本の企画を完成するまでの時間短縮。
- 利用者が自分の視聴データを入力した場合の、冒頭離脱・完視聴などの変化。

一定期間の反復利用と明確な時間短縮が確認できるまで、有料プランや決済を実装しない。数字は小規模検証のシグナルであり、市場全体の需要を意味しない。

## 実装順

1. 本PR: JSON契約、検証スクリプト、OSS活用方針を追加。
2. 次: research と video Specialistで、権利付き素材を前提に企画案と字幕案を作る。
3. 次: Colab用のWhisper→FFmpegパイプラインを別成果物として検証する。
4. 次: 出力ファイルの権利・類似度・字幕・音声QAを自動検査する。
5. 最後: 利用者が明示承認した場合だけ、手動公開フローを設計する。
