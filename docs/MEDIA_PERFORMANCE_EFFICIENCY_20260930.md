# 表情・口パク・意味単位の字幕強調と高速制作

更新: 2026-09-30 JST。正本は `config/media_performance_efficiency_policy.json`。
今回は調査・準備コード・ルール・回帰テストを追加する作業であり、動画制作を行わない。

## 次の制作で適用すること

ずんだもん・四国めたんの60秒動画では、発話に合わせた口の開閉と、台本の意味に沿った少数の表情変更を必須にする。通常・喜び・驚き・真剣・悲しみの固定プリセットを使う。意味が変わらない文では表情を保持し、毎文ランダムに変えない。待機側と無音区間は閉口。話者フォーカスは話者1.08倍・100%、待機側1.00倍・55%を維持し、上下運動で口パクを代用しない。

前回の静止画レンダラー選択は、この60秒テンプレートの要件を満たしていなかった。`scripts/media_performance_route.py` が短尺形式・実測目標からプロファイルを選び、口同期と表情変更の能力を持たない描画経路を出力前に拒否する。明示した静止画プロファイルは別用途として残る。準備計画の生成を「動画への適用完了」と呼ばない。意味単位の強調範囲を受け取る未対応rendererも、強調を無言で落とさず出力前に拒否する。

このスコープ内では本ポリシーが旧STATICの口パク・表情禁止規則に優先する。それ以外の用途では一般の静止画ルールを保持する。

## 素材と口の計算

YMM4公式のPSD素材マネージャーは、開いた口を上、閉じた口を下に並べて口パク設定する手順を示している [1]。初回だけ素材・目眉・口差分の位置と閉口状態を確認し、素材ハッシュとアンカー版を保存する。口を含む表情画像の上へさらに口を重ねる二重口は不可。素材が同じなら毎回差分を作り直さない。

YMM4にはRMSによる口パク音量計算の公式更新記録がある [2]。Python準備では、最終WAVを短い窓で読み、RMS・ヒステリシス・状態保持から CLOSED/HALF/OPEN のイベントを作る。これは音量連動の近似であり、母音別の正確な口形推定とは区別する。窓長や保持時間は本プロジェクトの調整値であって公式の推奨値ではない。BGMを混ぜた音声を解析しない。最終VOICEVOX音声だけを入力する。

音素時間が利用可能でも、speedScale変更後の完成WAVと整合する場合だけ採用する。通常の既知TTSでは追加ASRや別AIを使わず、実測WAVを計算する。音声は意味のまとまりで合成し、単語ごとの細切れ合成を避ける。

## 重要な「内容」を色で示す

「生命」「火星」などの単語を抽出して囲う方式は使わない。通常の字幕のまま、例えば「生命が見つかったわけではない」という注意点や「水が複数回作用した」という結論のまとまりを色変更する。囲み・単語カード・角括弧の追加・文字サイズの段差は不要。

字幕原文上の start/end をPythonが検査し、明示した一箇所だけ着色する。同じ語句が二度出ても全部を自動着色しない。強調句は改行可能で、強調のために全文を不可分にして縮小したり画面外へ押し出したりしない。原文は変えない。60秒で最大3箇所・1意味ブロックで最大1箇所、強調0も許可する。reason と PHRASE/CLAUSE の明示が必要で、文字数だけで意味判定したと扱わない。

Jevを使う場合は、Python/台本側が用意した候補IDをChoiceで選ぶ。自由文JSONや文字位置の計算をJevへ任せない。表情も同様に固定Enum。認証情報や許可がない場合、明確な既定ルートはPython、判断が必要な箇所は司令部が処理する。別の有料モデルへ切り替えない。

YMM4の文字制御タグには部分色変更がある [3]。タグは字幕側だけに使い、VOICEVOXの voice_text や二列CSVの発話へ混ぜない。Windowsで字幕タグと描画を確認するまでは、計画sidecarをYMM4自動適用済みとしない。

## 時間を減らす依存関係

| 変更 | 再利用 | 作り直す部分 |
|---|---|---|
| 字幕色・強調範囲 | 音声、実測時間、口イベント、素材 | 字幕レイアウト、最終映像 |
| 目眉の表情 | 音声、実測時間、口イベント | 対象表情の合成、最終映像 |
| 音声文章・速度 | 素材、変更のない台詞の音声 | 対象WAV、下流の口・字幕・タイムライン |
| 素材・アンカー | 音声とタイミング | 対象素材合成、小さい位置確認fixture |

エンジンと素材の初回取得時間は cold start として分ける。継続時は起動済みVOICEVOX・音声ハッシュ・固定素材・フォントを使い回す。音声と素材取得は独立レーンで並列。口イベントと字幕時間はWAV完成後に計算する。最終統合は一人の書き込み担当が行う。Shortは一回の最終encode、長編はScene checkpointを維持する。

ハードウェアencodeは使用可能な環境で同じ短いfixtureをソフトウェアencodeと比較し、時間・decode・画質を確認した場合のみ選ぶ。公式に高速化機能が存在することを、手元で検証済みの速度改善率と取り違えない。今回の改修では動画を作らないため、10分達成や改善率は未測定。

## YMM4連携の境界

公式の台本CSVはキャラクター名とセリフの二列 [4]。追加の表情・秒数欄が自動反映されると説明しない。公式SRT/SUB読み込みは時間情報をもとに配置する [5]。既成WAVを使う字幕は通常テキスト項目とし、`>> キャラクター名:` は入れない。この接頭辞はボイス項目を生成し、二重音声を招くためである。

基準 `.ymmp` とPSDの実際の自動口パク・表情・字幕色はWindowsで確認が必要。現在の追加コードは純粋な準備計画で、YMM4操作・アニメーション合成・完成映像の検証は未実施。次の動画では対応renderer/editorと固定素材fixtureが必要で、静止画経路へ黙って戻さない。

## マルチエージェントを使う条件

司令部は目的・最終統合・例外判断、Jevは短いtyped判断、Pythonは計算・整形・検証を担当する。調査と台本は一つの判断工程としてまとめる。相互に独立した調査・実装・検証にだけ最大3レーンを割り当てる。単純な口イベント計算・字幕整形を何体ものAIへ重複依頼しない。

Workerは現在の利用可能性・分野別品質・成功率・429・速度から選び、古い順位を固定しない。同じ出力への並列書き込みは不可。成功したレーンは再実行しない。重要な食い違いだけ独立検証へ渡す。品質失敗率、実処理時間、手戻り回数、cache hit、外部呼出数を冷開始・温開始で別に測る。

## 再利用の追加実装（同日追記）

`media_voice_cache.py` と音声生成スクリプトは、読み上げ文章・engine版・話者style・速度・イントネーション・発音辞書・出力形式が一致する生成済みWAVを、hashとPCM構造を確認して再利用する。cache hitでは audio_query / synthesis / 音声変換を繰り返さない。音声キャッシュの既定保存先は `.media-cache/voicevox-wav`。cache missだけ合成し、変更のない他の台詞は保持する。素材キャッシュの既存resolverも継続して使う。

`measure_mouth_cached()` は音声hash・解析設定・engine/style・実装版の一致を検証し、別の実行でも口イベントを再利用する。`build_plan()` の呼び出し側は `mouth_cache_dir` を明示して永続再利用を有効にする。checksum・schema・時間範囲が不正ならその派生計算だけをやり直す。途中ファイルを成功済みcacheと扱わない。表情/字幕色/強調だけの変更では音声キーも口解析キーも変えない。

台本の構成、YMM4基準プロジェクト、キャラクター差分、フォント、素材、VOICEVOXエンジンは初回準備として保存し、次回は既存IDと版を確認して使う。既存完成Artifactを消して作り直す方式は禁止。冷開始と温開始を区別して実測し、まだ測っていない短縮率を宣伝しない。


## 再利用基盤の欠損対策・基準プロジェクト複製

表情パックは台帳の存在だけでは再利用しない。抽出済み元PNG全体、台帳、全登録画像のhash、両キャラの口・目・眉・本体の必要枚数を検査する。旧台帳は初回のみ再構築し、その後は一致時に透明化や画像生成を省略する。再構築の検査に失敗した場合は既存パックを保持する。

素材準備Workflowは元素材と派生パックをActions cacheから復元し、最終検査後に保存する。配布Artifactは30日保持する。Actions cacheは期限や退避のある高速化用保存で、永久保管の保証ではない。素材と検証済みWindows基準プロジェクトは制作端末でも保持する。

`python scripts/reuse_ymm4_baseline.py --baseline <基準.ymmp> --receipt <検証台帳.json> --destination <今回.ymmp>` は、Windows確認済みの基準を同じフォルダへ複製する。台帳には baseline_sha256、windows_preview_verified、mouth_sync_verified、semantic_expressions_verified、caption_phrase_color_verified、reviewer、verified_at と、assets（path/sha256の配列）が必要。相対素材パスを維持し、変更済み素材や未確認基準は拒否する。編集中の今回プロジェクトを上書きしない。

このコマンドは基準の再利用であり、Windows確認の代行やsidecarの自動適用ではない。検証台帳のtrue値を実際のプレビューなしで設定しない。口・表情・字幕色のWindows完成映像確認は引き続き未実施。
