# ずんだもん・四国めたん リアクション／字幕 永続標準

この文書は、ずんだもん・四国めたんを使う動画で毎回同じ素材を探したり、同じ素材を再ダウンロードしたり、上下バウンスだけで動きを済ませたりしないための恒久ルールです。正本は `config/media_character_reaction_cache_policy.json` で、この文書は人間が読みやすい説明版です。

## 1. 素材は「一度取得 → 一度整形 → 使い回す」

原本は登録済み `zm_shell_20230806` を使います。動画ごと・シーンごと・セリフごとに検索しません。`.media-cache/assets/characters/zm_shell_20230806` に検証済み原本があれば再ダウンロード禁止です。原本が無い場合だけ、既知の登録URLから取得します。

原本から `scripts/prepare_character_reaction_pack.py` を使い、`.media-cache/derived/zm-reaction-pack-v1` に派生リアクションパックを一度作ります。同じ source SHA と pack revision の組み合わせなら次回は即 `CACHE_HIT` とし、再整形しません。

派生パックは、黒背景キーの透過補正、PNG一覧のカテゴリ索引、ずんだもん／めたんの口・目・眉・腕・顔色・汗・涙などの把握、さらに `? / ! / 怒り / 強調 / focus flash` の決定論的な記号素材を含みます。これらの記号は外部から毎回取りに行かず、ローカルで生成して再利用します。

第三者の原本・派生画像そのものはRepositoryへコミットしません。公開・商用利用前の権利再確認はキャッシュ済みでも省略しません。

## 2. 口パクは「動いている」だけでは合格にしない

口素材が存在し、音声に合わせて切り替わっていても、顔の正しい位置に収まっていなければ失格です。口の差分は、原則として元の立ち絵と同じフルキャンバス座標を使うか、クロップ済み素材ならキャラクターごとの明示的なアンカー情報を持たせます。アンカー無しのクロップ口素材を目測で貼ることは禁止します。

ずんだもん・四国めたんの各キャラクターについて、最低でも `closed / small_open / open または wide_open` の3状態を本番前の軽量Fixtureで確認します。口が鼻・目・輪郭へ食い込んでいない、顔から浮いていない、二重口になっていない、透過処理で肌や線画を欠いていないことを確認します。1キャラにつき同時に有効な口レイヤーは1つだけです。

このFixtureは毎フレーム・毎セリフで繰り返しません。`source SHA / reaction-pack revision / character / output geometry / scale profile / anchor profile` が同一なら合格結果を再利用します。逆に、原本・パック・アンカー・スケール・出力寸法のいずれかが変わったら再確認します。

## 3. 動きは「上下するだけ」を禁止

喋り出しの小さなバウンスは補助演出として残してよいですが、それだけをキャラクターの動きにしてはいけません。会話の意味の切れ目で、最低でも表情・ポーズ・左右移動・寄り引き・傾き・視線・前後フォーカス・リアクション記号のいずれかを組み合わせます。

表情またはポーズは原則1〜2文以内に一度は意味に合わせて変えます。ずんだもんは質問・驚き・困り・ツッコミなどの反応を積極的に使い、めたんは説明・訂正・警告・呆れ・納得などに合わせて差分を切り替えます。話者は従来どおり拡大・明度・前面化でフォーカスし、聞き手にも必要に応じて視線や表情のリアクションを入れます。

口パク・目パチはYMM4＋VOICEVOXを第一選択とし、ヘッドレス実装でも同等の見た目を再現します。大きい動きを常時入れるのではなく、意味のある場所で動かして見やすさを守ります。

## 4. 読み方と字幕は別データ

VOICEVOXへ渡す読み上げ用文字列 `voice_text` と、画面へ出す `caption_text` を分離します。

たとえば読み上げは「エーアイ」「オープンエーアイ」「アンスロピック」「ハギングフェイス」のようなカタカナ発音で構いません。しかし字幕は原則として `AI`、`OpenAI`、`Anthropic`、`Hugging Face` と表示します。同様に `Reuters`、`Sam Altman`、`GPU`、`API`、`CEO` など、正式な英字表記がある固有名詞・技術語は英字を優先します。

カタカナ発音を字幕へ自動コピーすることは禁止です。日本語の助詞や説明文は日本語のままにし、英語の固有名詞だけ正式表記を使います。公式の日本語表記が標準の場合、またはユーザーが別表記を指定した場合のみ例外です。

## 5. 字幕は「文字数で切る」のではなく意味で切る

既存の1行最大文字数は画面安全性の上限であり、「15文字まで必ず詰める」という目標ではありません。まず句点・読点・文・節・自然な文節・助詞のまとまりなど、読み上げと意味の切れ目を探し、そこで早めに改行または字幕チャンクを切ります。最後に文字数や表示幅を確認します。

日本語の禁則処理を守り、行頭に句読点や閉じ括弧を置かず、可能な限り助詞・助動詞だけを次行へ孤立させません。`OpenAI`、`Anthropic`、`Hugging Face`、人名、製品名、略語、技術語、意味的に結びついた数値＋単位は途中で分断しません。文字コード単位の機械的スライスは禁止です。

表示幅を測れる場合は、単純な文字数より実際のピクセル幅を使います。長い不可分トークンが上限へ近づく場合は、トークンを割る前にフォントサイズ・字間・レイアウト側で安全に収めます。

## 6. 高速化の原則

レンダー開始後に全Shellを毎フレーム探索しません。リアクションパックの `inventory.json` は1レンダーにつき一度だけ読み、同じ解像度で使う拡大済み画像や合成済み表情はメモリまたは一時キャッシュで再利用します。口アンカー変換も出力Geometryごとに一度計算し、同一条件なら再利用します。

ネットワーク、検索、ダウンロードはレンダーのクリティカルパスから外します。素材準備は最大4並列まで、パック書き込みはSingle Writer、完成パックはatomicに切り替えます。速度のために字幕、権利、口パク、目パチ、表情、最終machine QAを削ってはいけません。

## 7. 動画制作前に必ず読む

この標準は `config/media_command_read_gate.json` の共通必読セットに含めます。新しいタブ・セッションでも会話Memoryだけを頼りにせず、Repositoryの現行版を読み直してから動画制作に入ります。

## 8. 今回の仕上がりから追加する既定値（2026-09-30）

- 字幕本文は強い緑・ピンクではなく、淡いミント `#B8E6C8` と淡いローズ `#F2C4D7` を使います。濃い縁取り `#08101B` と暗色の字幕板を残し、スマートフォン幅で読めるコントラストを確認します。
- 重要箇所は単語カードにせず、意味のまとまりを必要な時だけ淡い金 `#F6DB98` で示します。注意・訂正だけ淡い赤み `#E7A6AA` を使います。
- 長尺の会話解説は音声同期の口状態と意味に沿った表情presetを使います。字幕、表情cue、画面の見た目を別々に確認します。cue JSONがあるだけでは、実際に表情が切り替わった証拠になりません。
- 全身立ち絵一枚を台詞ごとに貼り替える静止レンダラーは、表情・口パク指定のある動画の完成経路に使いません。動作素材とYMM4/レンダラーの適用fixtureが確認できるまで完成品として通しません。
- 台本は「一つの質問→重要点3〜5個→何が変わるか→身近な例→限界・未確定点→一文まとめ」の順で組みます。関連機能はまとめ、専門語は最初に短く言い換えます。
- 4〜6分は一つの質問に絞った解説、6〜8分は短い発表まとめ、8〜12分は例・仕組み・影響・制約が追加理解につながる深掘りに使います。時間合わせの水増しはしません。
- 既存音声・公式出典画像・字幕タイミング・場面のうち変わっていないものは維持し、字幕色だけなら音声を、表情素材だけなら音声と出典素材を作り直しません。
